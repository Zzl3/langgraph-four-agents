本考核面向小影校招 AI Agent 开发岗位，评估业务理解、Agent 决策、工程实现、效果验证及学习改进能力。候选人须从四道项目题中任选一道，按统一规范提交 GitHub 项目。允许使用 AI 辅助工具，须如实记录使用范围、个人贡献与验证结果。

考核规则
考核目标：能理解业务问题，借助 AI 完成可运行项目，并用测试证明效果；观察工程基础、主动学习与改进能力。

完成范围：建议投入 3 小时，优先完成核心链路；记录实际用时和未完成部分。界面、线上部署、多 Agent、生产级 Runtime 均非必需。

技术选择：语言、模型与框架自选；可用 Google ADK、AgentScope、LangGraph 等，也可原生实现。框架名称不加分，能解释取舍与修改结果才有价值。

运行方式：CLI、HTTP API、Notebook 三选一；必须给出可复制的运行命令或执行步骤。截图、视频不能替代代码。

模型与工具：业务工具可以使用本地函数或 Mock。模型不可用时提供离线 Mock 入口并标明边界；Mock 只验证流程，不证明真实模型决策效果。

提交方式：提交题号、GitHub URL 和最终 commit SHA；私有仓库须让指定评审账号可读。所有材料放在同一仓库，不提交真实密钥或隐私数据。

Agent 决策要求：至少实现一个“模型选择动作 → 执行工具 → 观察结果 → 模型调整下一步或结束”的循环。允许采用预设流程作为执行骨架；仅有固定条件分支、自动重试或预设决策日志，不视为完成 ReAct 决策要求。

须提供至少两条执行路径的运行记录，体现模型根据不同工具结果调整动作。记录应包含步骤、工具参数、返回摘要、后续动作及简要决策依据，无须提交模型内部思维过程。项目须设置执行步数或工具调用次数上限，达到上限时返回明确的未完成状态。

GitHub 交付规范
项目目录可按技术栈调整，但须包含下列代码、文档与验证材料。文档应准确说明需求、设计取舍、运行结果及已知限制，不设篇幅要求。

素材审核与发布排期 Agent
项目要求

用户与目标:帮助内容团队找出待处理素材，形成无冲突、可确认的发布排期。
输入与材料:素材 ID、元数据、发布时间要求、已有排期与审核规则；提供素材读取、规则检查、时段查询和排期草稿保存工具。
交付结果:每项素材的审核状态、风险原因、建议时段、待确认项、草稿保存状态。仅保存草稿，不接真实发布。
动态决策:模型根据风险或时段冲突，选择补查、替代时段、请求确认或阻断；未经用户同意不得擅自改变硬性发布要求。
必须验收:正常排期；素材信息缺失；规则风险；时段冲突；重复提交；保存失败。
参考实例：素材 M01 无风险，用户要求 18:00，但该时段已占用、19:00 可用。模型建议 19:00 并标记待确认；不得称为已发布。相同请求重复保存只产生一份草稿；保存失败须明确返回失败。

审核要点：核对风险、冲突、确认状态与保存结果；更换占用时段并重复提交。高分依据是冲突调整、确认边界与防重复；越权发布或虚报保存成功属于关键缺陷。

内容任务规划 Agent
项目要求

用户与目标：帮助运营人员在预算与截止时间内完成一份内容活动方案。
输入与材料：主题、预算、截止时间；合成素材、工具费用与耗时表。提供素材检索、脚本生成、成本估算、方案保存工具。
交付结果:任务计划、步骤状态、工具结果、费用合计、已保存方案或未完成原因。
动态决策:模型根据成本超限、工具错误或部分成功结果，调整计划、选替代方案或停止；保留已成功步骤的结果。
必须验收:正常完成；缺预算或截止时间；工具失败；预算超限；重复执行。失败步骤续跑属于加分项。
参考实例：预算 10 个模拟单位；初始方案估算 12，替代方案估算 8。模型观察到超预算后改选 8 的方案，再估算和保存。若没有可行方案，返回未完成及缺口；不能把失败步骤记为成功。

审核要点：核对预算计算、步骤依赖与实际状态；注入一次失败，观察是否调整计划且保留成功结果。高分依据是合理重规划；无状态、无失败处理只能证明完成串行调用。




企业知识问答 Agent
项目要求

用户与目标：帮助员工找到制度或产品问题的可靠答案。
输入与材料：问题及可选对话历史；带文档 ID、版本日期的合成 FAQ 或制度。提供文档检索与片段读取工具。
交付结果：回答、引用文档 ID 与原文片段、资料缺口、任务状态。
动态决策：模型根据检索结果选择补充检索、读取原文、追问或停止；资料冲突时说明冲突并查证，不凭空选一个答案。
必须验收：明确答案；文档冲突；资料外问题；改写后的相似问题；上下文追问；工具失败。
参考实例：规则 D01 写明“报销期限 30 天”，D02 写明“15 天”，未给适用范围与优先级。问“报销期限多久”时，应列出冲突与引用，并请求确认适用制度；不能擅自回答 15 天。只检索到 D01 且无冲突时可依据 D01 回答。

审核要点：检查引用原文是否支持回答；替换文档内容，核对答案与动作是否改变。高分依据是检索改进和冲突处理；无依据回答或错误引用属于关键缺陷。




短视频脚本 Agent
项目要求：

用户与目标：帮助创作者生成有事实依据、满足时长限制的可编辑脚本。
输入与材料：主题、受众、平台、目标时长、风格；产品素材与品牌规则。提供素材检索、时长估算、规则检查工具。
交付结果：标题、分镜、旁白或字幕、预计总时长、素材来源 ID、风险与任务状态。
动态决策：检索无结果时由模型决定改写查询或请求补充；时长或规则检查不通过时，调整脚本并再次检查，或说明无法满足。
必须验收：正常生成；缺关键信息；无素材；工具失败；超时长后的修正或明确失败。
参考实例：素材 P01 仅包含“支持字幕”的产品事实，用户要求生成 30 秒脚本。首稿估算为 38 秒时，模型应根据检查结果压缩脚本并重新估算；若修正结果为 28 秒，输出应包含分镜、P01 引用及总时长。无效果数据时，不得添加“效率提升 80%”等结论。项目须提交实际生成与检查结果。

审核要点：将素材 ID、分镜时长和检查结果逐一对应；改变时长或检索结果，核对下一步动作是否调整。高分依据是有效修正与事实可追溯；编造产品事实属于关键缺陷。
