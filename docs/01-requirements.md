# 需求与验收

## 用户和目标

内容团队需要从待处理素材形成无冲突、可确认的发布排期。项目只生成本地草稿，不执行真实发布。

## 输入与输出

输入包含素材 ID、日期、要求时段，可选素材元数据、已有占用时段和审核禁词。输出逐项记录审核状态、风险、缺失字段、建议时段、确认要求和草稿保存状态，并明确 `published: false`。

## 验收标准

- 正常排期可以保存草稿；重复提交只产生一份草稿。
- 缺失素材或必需信息时返回未完成状态及原因。
- 规则风险阻断草稿保存。
- 用户要求的时段已占用时，模型/决策器可根据查询结果选择空闲时段；替代时段必须等待用户确认。
- 保存失败须准确返回失败状态，不得声称已保存。
- 工具调用存在上限；达到上限时返回 `incomplete`，保留已完成步骤。
- 至少两条轨迹须展示不同工具结果带来的后续动作变化。
- 至少三组输入、输出和 Trace 覆盖正常、资料不足及工具失败场景。

## 范围与边界

规则和素材均为合成数据。草稿保存在本地 SQLite；没有线上发布、真实排期平台同步、权限系统或草稿取消/过期流程。mock 结果仅验证执行流程，不证明真实模型决策质量。
