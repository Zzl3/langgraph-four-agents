# AI 使用记录

## 我的工作

我提供并梳理了完整考核题目和统一交付规范，负责确定项目选题与优先级：从“任选一道”的要求出发，最终选择第 1 题“素材审核与发布排期 Agent”，把最初的四题实现收敛成一道可评审的题目，并要求删除其余题目的代码、数据、示例和测试，避免范围发散。

我把题目验收要求转成了实现边界和交付重点，并在过程中持续校正方向：

- 明确核心链路要覆盖素材读取与审核、时段查询、冲突后的替代建议、幂等保存和保存失败反馈。
- 强调替代用户指定时段必须等待用户确认，只能保存草稿，不能擅自发布或把失败说成成功。
- 要求项目能离线跑通，保留正常、资料不足、工具失败等输入、实际输出和执行轨迹，并设置工具调用上限；同时要求文档如实区分 mock 流程验证和真实模型效果。
- 根据本机资源占用要求停止运行 Ollama，改用离线 mock 验证；并要求另一个 agent 模拟评审者视角，检查实现与相关文档，而不只看代码能否运行。
- 发现项目范围与“任选一道”不一致后，我明确选择第 1 题并要求缩减；最后根据独立评审对交付记录的提醒，提供实际投入时长约 3 小时的估算。

以上是我在本项目中承担的需求澄清、范围管理、业务约束决策和评审组织工作。实际投入时长约 3 小时，为我的估算。

## AI 辅助范围

Codex 辅助完成了 LangGraph 执行循环、排期工具、结果校验、测试用例、运行示例及项目文档，并根据我的范围和约束要求进行修改。独立评审 agent 对工作树进行了只读检查，没有修改项目文件，也没有运行测试或 Ollama。

项目默认使用离线 mock。它用于验证工具流程、业务约束和失败处理，不代表真实模型决策效果。历史上曾运行本地 Qwen 模型并保存两条排期轨迹，详情见 `docs/03-evaluation.md`；这些轨迹不是本次单题收敛后的重新实测。按我的要求，收敛版本的验证没有再启动或运行 Ollama。

## 验证与分工边界

Codex 完成了具体的 LangGraph 节点与状态循环、工具实现、证据校验、自动化测试、示例生成和文档编写；27 项自动化测试由 Codex 在本地运行，结果记录在 `examples/test-results.txt`。我负责需求与验收澄清、选题和范围取舍、业务风险边界、模型使用约束以及组织独立评审。我的贡献不包含未实际发生的手工编码或测试执行；AI agent 的评审也不等同于我本人逐项人工复核。
