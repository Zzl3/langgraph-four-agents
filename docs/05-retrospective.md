# 复盘

最需要谨慎处理的是“建议替代时段”与“用户已同意修改”的边界。实现中将二者分开：检测到冲突后可以准备替代草稿，但必须返回待确认状态，且 `published` 永远为 false。最终结果由工具轨迹重建，可避免模型把保存失败描述成成功。

另一个难点是相同请求重试与并发时段竞争。SQLite 幂等键让重复提交返回同一份草稿；写入事务重新检查其他本地草稿的时段，发生竞争时拒绝写入并让流程刷新时段查询。

历史真实模型试跑显示，工具调用参数错误可在错误观察后修正；也说明两条成功轨迹并不足以证明模型在更广输入下稳定。当前离线测试只能验证约束执行和错误处理。下一步应接入有授权的测试排期服务，扩展规则边界与并发测试，并对更多模型决策轨迹进行人工抽查。提交者应自行补记实际投入时长及个人贡献。
