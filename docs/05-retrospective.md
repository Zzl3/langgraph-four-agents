# 复盘

最难的问题是把模型建议与业务约束分开：排期替代时间要等待用户确认；预算与时限必须有估价依据；问答要读取并引用所有相关原文；视频事实必须绑定素材来源。真实模型轨迹展示了验证器的价值：它拒绝了超预算方案、缺少第二份原文的冲突结论，以及没有来源事实的脚本。

本地 Qwen 在排期冲突和空闲时段两条路径中能根据工具结果继续决策；但在规划、问答和脚本案例中，模型重复错误动作或未遵循观察，真实模型动态决策仍未覆盖四题。第二模型评审还发现问答数字冲突判定依赖句式相同、时限缺口报告没有扣除本次耗时。我据此扩充了异句式冲突检测，但第二模型复核发现仅共享主题词仍会把“提交期限”和“审核期限”误当成同一指标；现在按句子和属性词配对数值，属性无法对齐时返回资料不足。另阻止 `insufficient` 掩盖已验证冲突，并让缺口和保存使用相同剩余时限计算。测试现在覆盖这些反例。下一步应改进结构化工具调用和失败后的显式下一步约束，并在可用模型资源时复跑每题的正常、边界和工具失败案例。不能用增加离线固定分支替代真实模型验证。
