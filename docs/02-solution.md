# 方案

`src/engine.py` 的 `build_graph(task)` 按 `schedule`、`plan`、`qa`、`video` 分别编译四个任务绑定的 LangGraph StateGraph；每个图使用独立节点名和任务校验，共享 decide → execute → decide 执行骨架及条件边。达到调用上限进入对应任务的 limit 节点并保留已完成步骤与实际保存状态。真实决策器向 OpenAI 兼容接口传入请求、可用工具与观测，要求 JSON 动作；请求有可配置超时、不自动重试，并在每轮关闭客户端；离线决策器是明确的规则模拟，仅验证业务流程。`src/tasks.py` 提供合成业务工具及策略。SQLite 的唯一键基于原始业务请求，保证相同请求重复提交只产生一条记录；若同一请求的新建议与已有内容不同，返回幂等冲突而不覆盖；模型决定替代时段时仅保存待确认草稿。

测试使用 LangGraph 1.2.18 的 StateGraph、条件边和状态传递；未实现框架本身。业务资料在 `data/`，允许问答与脚本的测试请求覆盖资料。追问无明确主题时，仅引用最近一条包含主题的用户历史，不使用助手历史；明确新主题时不拼接旧历史。真实模型必须完成系统提供的基准查询后才能输出有依据的结论。运行记录无隐藏思维链，只有动作理由。

当前重要限制：真实模型的自然语言输出尚无系统性事实校验；资料检索使用有限同义词和字符二元组，另对常见问题意图做保守检查；二者均无法保证语义蕴含和召回率；时长采用每秒最多 4 个非空白字符的简化语速下限及分镜设定时长估算，并非真实录音测量；脚本品牌检查使用禁词、有限中性旁白和素材原文严格匹配，无法理解同义表述或校验复杂事实。冲突检测只对句子上下文、同主题和属性词均可对齐的数字差异，或同形的肯否相反作确定判断；属性缺失、属性不同及其他句式返回资料不足，仍不能证明资料一致。仅保存工具增加了部分前置证据约束，不能视为生产安全保证。

决策器失败时图保留已发生工具轨迹。最终结果对保存、文档引用、分镜和检查结果做证据一致性验证；对自然语言语义的完整性仍无法保证。模型接口除本机模拟 HTTP 与替身客户端测试外，还用本机 Ollama/Qwen 做了真实决策试跑；两条排期路径成功，规划、问答和视频路径失败，详见评估文档。模拟 HTTP 与替身客户端本身不能证明真实模型推理质量。

规划支持带时区的绝对截止时间：运行时转换为剩余小时，保存时重新核对时限；相对时限也会扣除本次图运行的耗时，幂等键使用原始截止时间。按参数匹配的 `fail_when` 仅用于合成故障测试；失败时排期结果逐项保留已保存与失败状态。

排期默认审核规则位于 `data/schedule_rules.json`，可对请求附加禁词；视频默认规则位于 `data/brand_rules.json`，请求可追加禁词或收紧允许的画面模板。视频默认三镜头，根据有限的受众、平台和风格模板调整开场和画面，修剪后重新估时，极短时长可能删去非事实镜头。

本地排期查询会合并同一 SQLite 文件中的其他草稿占用，排除本素材对应的幂等键以支持重试。保存时使用 `BEGIN IMMEDIATE` 在同一事务内检查并写入；若并发请求占用时段，返回 `slot_conflict`，离线决策器重新查询并选择候选时段。待确认草稿在本地也作为暂占，当前无取消或过期功能；隔离的 runtime 和外部排期服务并不共享锁，不能防止外部系统在查询后变更排期。损坏、不兼容或相互冲突的本地草稿会导致查询失败，不会跳过。

规划先按素材关键词与主题做字面匹配，再从可配置费用表逐项估价；无匹配素材不生成方案。每个步骤费用和耗时使用十进制求和，小数输入仍通过 JSON 数值接口传递。实际项目若需复杂语义素材检索或严格财务精度，应替换对应组件。保存时检查素材 ID、脚本和估价均来自工具；计划中的内容制作步骤标记为 `planned`，工具步骤单独记录，保存方案不表示活动已经执行；当请求自带 `plan_data` 时，该资料也计入幂等键。

内容规划可选用 `--run-id` 持久化每次工具观察，`--resume` 加载原轨迹并在离线模式重试最近失败的步骤；真实模型模式会收到恢复提示并自行决定。签名绑定业务输入及素材费用表，允许移除模拟故障开关；使用 SQLite 版本条件更新阻止并发覆盖。相对截止时间包含两次进程间的等待，调用上限按所有轨迹累计。这是项目自建的业务轨迹存储，并非 LangGraph 内置 checkpointer；本地记录假设数据库可信，不是分布式工作流服务，也不恢复执行中的工具调用。

模型构造的排期草稿使用固定字段和精确待确认文案，原时段可用时不能虚称冲突；排期摘要从实际工具轨迹重建。规划步骤的依赖必须指向先前步骤，保存方案字段及步骤字段受到约束；规划、问答和视频的最终交付移除未经工具核验的额外字段。自然语言决策理由和规则式语义判断仍不构成完整事实保证。

`--trace-file` 在每次工具调用后写入独立 JSONL 事件，便于观察长时间运行；结束时追加结果。它与内容规划的续跑检查点不同，不用于恢复状态，不覆盖现有文件；写入失败通过 `trace_error` 报告，而已完成的业务操作仍按真实状态返回。

真实模式会压缩发给模型的重复轨迹，但仍完整保留公开 Trace；问答还会把尚未读取的文档 ID、下一项读取动作和证据冲突检测状态作为结构化上下文传入；规划每轮收到扣除已耗时后的剩余时限、预算、各选项最新估价及是否已有匹配素材脚本（脚本内容与方案选项无关）；视频品牌检查失败后会传入失败分镜、风险、修订建议及所有相关检索事实，并区分“改稿后重新估时”和“已估时、待品牌检查”两个阶段。它还会对同参数的已成功文档读取、检索和检查增加重复调用保护；时段查询仍可重查，以反映保存竞争后的新占用。这些是工具调用预算和证据提示，不会替模型生成未完成答案；最终状态仍由实际工具观察与证据校验决定。结构化提示已由本地 HTTP 契约测试覆盖，仍需真实模型验证其是否改善决策。
